# 分发指令模板（task_prompt）

> 编排分发时发给目标 agent 的标准指令格式。
> 关键约定：**[DONE] 结尾 + 一次回复即完成（防 ping-pong）**。

## 模板

```text
【任务】<子任务描述：做什么、做到什么程度、边界是什么>
【来源】主 agent 编排分发（用户指令：<原始用户指令摘要>）
【要求】
1. 执行完成后一次性回复结果，回复以 [DONE] 结尾
2. 不要追问、不要确认、不要中间汇报（除非遇到阻塞性错误）
3. 如果遇到无法完成的情况，回复以 [FAILED] 结尾并说明原因
【产出】
1. 结果写到：<目标位置，如 outputs/images/2026-08-30/>
2. 回复里给出：产出路径 + 结果摘要（3-5 句）
```

## 示例（画图任务）

```text
【任务】绘制小遥生态产品矩阵架构图：四层堆叠（L1 基础设施五件套 / L2 工具层 /
L3 AI 能力层 / L4 生态层）+ 双入口大卡 + 商业逻辑链箭头闭环 + 四色图例。
深色科技风，信息密集型，文字清晰可读。
【来源】主 agent 编排分发（用户指令：让小光把生态产品矩阵画出来）
【要求】
1. 执行完成后一次性回复结果，回复以 [DONE] 结尾
2. 不要追问、不要确认、不要中间汇报
3. 如果遇到无法完成的情况，回复以 [FAILED] 结尾并说明原因
【产出】
1. 结果写到：outputs/images/2026-08-30/xiaoyao-ecosystem/
2. 回复里给出：产出路径 + 结果摘要（3-5 句）
```

## 示例（并行调研任务）

```text
【任务】调研 Patina 的竞品与市场：找出 3-5 个同类时间追踪工具，对比功能交集、
协议（开源/闭源）、平台支持，给出 200 字以内的竞品结论。
【来源】主 agent 编排分发（用户指令：调研一下这个 TimeTracker 软件）
【要求】
1. 执行完成后一次性回复结果，回复以 [DONE] 结尾
2. 不要追问、不要确认、不要中间汇报
3. 如果遇到无法完成的情况，回复以 [FAILED] 结尾并说明原因
【产出】
1. 结果直接写在回复里（不落盘）
2. 回复里给出：竞品清单 + 对比结论 + 来源标注
```

## 重试时的指令（第 2/3 次）

```text
【任务】<原子任务描述，与首次相同>
【来源】主 agent 编排分发（用户指令：<原始指令>）——第 N 次重试
【上次失败原因】<失败原因摘要>
【要求】
1. 执行完成后一次性回复结果，回复以 [DONE] 结尾
2. 不要重复已完成的部分：<已完成的产出/结论>
3. 如果再次遇到相同问题，直接以 [FAILED] 结尾并说明原因
【产出】同首次
```
